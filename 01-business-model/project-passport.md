## 2. БИЗНЕС-КОНТЕКСТ

**Проблема:**
Существующие календари и планировщики ориентированы на фиксацию точечных событий (встреч) в привязке к жёсткому времени. Пользователи испытывают трудности при планировании комплексных списков дел на день, когда важен не столько точный час, сколько сам факт выполнения набора задач в течение суток. Отсутствует удобный инструмент для группировки задач по дням с гибкой системой напоминаний, не перегружающий интерфейс событиями.

**Решение:**
Разработать мобильное приложение, позволяющее создавать «Папки» (контейнеры задач) и управлять отдельными задачами внутри них. Приложение предоставляет возможность установки напоминаний на конкретные задачи (дата, время), обеспечивая фокус на выполнении, а не на планировании. Данные синхронизируются с серверной частью через REST API.

---

## 3. ЦЕЛИ ПРОЕКТА

1. **Обеспечить удобное управление задачами:** реализовать интуитивный мобильный интерфейс для создания, редактирования и удаления папок, задач и подзадач.
2. **Внедрить гибкую систему уведомлений:** разработать серверную логику для отправки push-уведомлений о предстоящих задачах.
3. **Обеспечить надёжное хранение данных:** создать серверную часть с REST API и базой данных для синхронизации данных между устройствами пользователя.

## 4. КЛЮЧЕВЫЕ ПОКАЗАТЕЛИ УСПЕХА

| Показатель | Целевое значение |
|---|---|

## 5. КЛЮЧЕВЫЕ РИСКИ

| Риск | Стратегия реагирования |
|---|---|
| **Сложность реализации Push-уведомлений** | Выделить время на изучение Firebase Cloud Messaging (FCM) на ранних этапах, использовать готовые библиотеки-обёртки. |
| **Потеря данных при отсутствии сети** | Обязательная реализация локального кэширования (SQLite) в мобильном приложении с последующей синхронизацией при появлении интернета. |
| **Неверная оценка трудозатрат на UI** | Использовать стандартные компоненты Material Design для ускорения разработки интерфейса. |
