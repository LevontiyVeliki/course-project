# Техническое задание

## Мобильное приложение «Plan Day» (TaskPlanner)

**Автор:** Папикян Л.А.  
**Траектория:** В. Мобильная разработка (Android + Spring Boot Backend)  
**Версия:** 1.0  
**Дата:** 2026

---

## 1. Общие сведения

### 1.1 Назначение системы

Мобильное приложение «Plan Day» предназначено для управления личными задачами и списками дел. Приложение обеспечивает создание иерархических структур «Папка → Задачи», синхронизацию данных с серверной частью через REST API и работу в оффлайн-режиме.

### 1.2 Цель разработки

Разработать мобильное Android-приложение с серверной поддержкой, обеспечивающее:
- удобное управление задачами и папками;
- гибкую систему приоритетов (LOW / MEDIUM / HIGH / URGENT);
- надёжное хранение данных с синхронизацией через REST API;
- работу без интернета с последующей синхронизацией.

## 2. Требования к функциональности

### 2.1 Аутентификация и авторизация

| ID | Требование |
|---|---|
| FR-01 | Регистрация нового пользователя (логин, email, пароль) |
| FR-02 | Аутентификация по логину и паролю, выдача JWT-токена |
| FR-03 | Хранение JWT-токена на устройстве в SharedPreferences |
| FR-04 | Выход из аккаунта с очисткой локальных данных |

### 2.2 Управление папками

| ID | Требование |
|---|---|
| FR-05 | Создание папки с названием и выбором приоритета (цвета) |
| FR-06 | Просмотр списка всех папок пользователя |
| FR-07 | Удаление папки с каскадным удалением всех задач |
| FR-08 | Синхронизация папок с сервером при наличии соединения |

### 2.3 Управление задачами

| ID | Требование |
|---|---|
| FR-09 | Создание задачи с названием, описанием, датой и временем |
| FR-10 | Просмотр списка задач внутри папки |
| FR-11 | Редактирование любого поля задачи |
| FR-12 | Отметка задачи как выполненной через чекбокс |
| FR-13 | Удаление задачи |
| FR-14 | Добавление подзадач к задаче |
| FR-15 | Синхронизация задач с сервером |

### 2.4 Профиль и настройки

| ID | Требование |
|---|---|
| FR-16 | Просмотр профиля (логин, email, дата регистрации, кол-во задач) |
| FR-17 | Загрузка и сохранение фотографии профиля |
| FR-18 | Изменение полного имени пользователя |
| FR-19 | Смена пароля |
| FR-20 | Выбор цветовой темы приложения (5 тем) |

### 2.5 Синхронизация и оффлайн

| ID | Требование |
|---|---|
| FR-21 | Работа приложения без интернета (чтение, создание, редактирование) |
| FR-22 | Автоматическая синхронизация при восстановлении соединения |
| FR-23 | При входе в аккаунт — полная загрузка данных с сервера |

## 3. Нефункциональные требования

| ID | Категория | Требование |
|---|---|---|
| NFR-01 | Производительность | Время ответа API ≤ 500 мс (95-й перцентиль) |
| NFR-02 | Надёжность | Данные не теряются при отсутствии сети |
| NFR-03 | Безопасность | Пароли хранятся в виде BCrypt-хешей, токены — JWT HS256 |
| NFR-04 | Совместимость | Android 8.0 (API 26) и выше |
| NFR-05 | Объём | Приложение занимает не более 50 МБ |
| NFR-06 | Тестируемость | Покрытие кода серверной части тестами > 40% |

---

## 4. Технические ограничения

| Параметр | Ограничение |
|---|---|
| Платформа клиента | Android (Kotlin, минимум API 26) |
| Платформа сервера | Java 17, Spring Boot 3.x |
| База данных (сервер) | PostgreSQL 14+ |
| База данных (клиент) | SQLite (встроенная в Android) |
| Аутентификация | JWT (HS256, срок действия 24 ч) |
| Сеть | HTTPS для production; HTTP допустим при локальном запуске |

## 6. Критерии приёмки

| Критерий | Целевое значение |
|---|---|
| Количество экранов приложения | ≥ 5 (реализовано 8) |
| Количество REST-эндпоинтов | ≥ 8 (реализовано 15) |
| Покрытие кода тестами (основной слой) | > 40% (слой `data` — 97%) |
| Работа в оффлайн-режиме | Обязательно |
| Синхронизация с сервером | Обязательно |
