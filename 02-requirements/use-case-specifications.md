# Спецификации прецедентов

Детальное описание двух ключевых сценариев использования системы.

## UC3: Создать список дел

| Поле | Описание |
| **ID** | UC3 |
| **Название** | Создать список дел |
| **Акторы** | Пользователь |
| **Краткое описание** | Пользователь создаёт новый список дел, привязанный к определённой дате. |
| **Предусловия** | Пользователь аутентифицирован в системе. |
| **Постусловия** | В системе создан новый список дел, отображающийся в интерфейсе пользователя на выбранную дату. |

### Основной поток событий

1. Пользователь нажимает кнопку «Создать список» на экране 
календаря или списка дел.
2. Система отображает форму создания списка с полями:
«Название», «Дата исполнения».
3. Пользователь вводит название списка (например, «Рабочие задачи»).
4. Пользователь выбирает дату исполнения (по умолчанию — текущая дата).
5. Пользователь нажимает кнопку «Сохранить».
6. Система проверяет корректность введённых данных (название не пустое, дата валидна).
7. Система создаёт новый объект `СписокДел`, связывает его
с текущим пользователем, присваивает статус «АКТИВЕН».
8. Система сохраняет список в базе данных.
9. Система возвращает пользователя на экран просмотра списка дел на
выбранную дату, где отображается вновь созданный список.

### Альтернативные потоки

- **6а. Некорректные данные:**
  - Если название пустое, система выводит сообщение «Название списка не может быть пустым».
  - Если дата не выбрана или имеет неверный формат, система
выводит сообщение «Выберите корректную дату».
  - Возврат к шагу 2.

- **7а. Ошибка сохранения:**
  - Если при сохранении возникла ошибка БД или сети, система 
выводит сообщение «Не удалось создать список. Попробуйте позже.».
  - Прецедент завершается.

## UC6: Добавить задачу в список

| Поле | Описание |
| **ID** | UC6 |
| **Название** | Добавить задачу в список |
| **Акторы** | Пользователь |
| **Краткое описание** | Пользователь добавляет новую задачу в существующий список дел. |
| **Предусловия** | Пользователь аутентифицирован. Выбран конкретный список дел. |
| **Постусловия** | В выбранном списке появляется новая задача. |

### Основной поток событий

1. Пользователь открывает существующий список дел (например, нажав на него в общем списке).
2. Система отображает детали списка и перечень вложенных задач.
3. Пользователь нажимает кнопку «Добавить задачу».
4. Система отображает форму с полем «Описание задачи» и опциональным выбором приоритета.
5. Пользователь вводит описание задачи (например, «Позвонить клиенту»).
6. Пользователь при необходимости изменяет приоритет (по умолчанию «Средний»).
7. Пользователь нажимает кнопку «Добавить».
8. Система проверяет, что поле описания не пустое.
9. Система создаёт объект `Задача`, связывает его с текущим списком,
присваивает статус «ОЖИДАЕТ», вычисляет порядковый номер (максимальный в списке + 1).
10. Система сохраняет задачу в БД.
11. Система обновляет экран списка, отображая новую задачу в конце перечня.

### Альтернативные потоки

- **8а. Пустое описание:**
  - Система выводит сообщение «Введите описание задачи».
  - Возврат к шагу 4.

- **9а. Ошибка сохранения:**
  - Система выводит сообщение об ошибке.
  - Прецедент завершается.
