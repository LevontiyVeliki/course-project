# Спецификации прецедентов

Детальное описание двух ключевых сценариев использования системы.

---

## UC3: Создать список дел

| Поле | Описание |
|---|---|
| **ID** | UC3 |
| **Название** | Создать список дел |
| **Акторы** | Пользователь |
| **Краткое описание** | Пользователь создаёт новый список дел, привязанный к определённой дате. |
| **Предусловия** | Пользователь аутентифицирован в системе. |
| **Постусловия** | В системе создан новый список дел, отображающийся в интерфейсе пользователя. |

### Основной поток событий

1. Пользователь нажимает кнопку «Создать список» на экране списка дел.
2. Система отображает форму создания списка с полями: «Название», «Дата исполнения», «Цвет».
3. Пользователь вводит название списка (например, «Рабочие задачи»).
4. Пользователь выбирает дату исполнения (по умолчанию — текущая дата).
5. Пользователь при желании выбирает цвет папки.
6. Пользователь нажимает кнопку «Сохранить».
7. Система проверяет корректность введённых данных (название не пустое, дата валидна).
8. Система создаёт новый объект `СписокДел`, связывает его с текущим пользователем, присваивает статус «АКТИВЕН».
9. Система сохраняет список в базе данных и синхронизирует с сервером.
10. Система возвращает пользователя на экран со списком папок, где отображается вновь созданная папка.

### Альтернативные потоки

- **7а. Некорректные данные:**
  - Если название пустое — система выводит сообщение «Название списка не может быть пустым».
  - Возврат к шагу 2.

- **9а. Ошибка сохранения:**
  - Если при сохранении возникла ошибка сети — данные сохраняются локально, синхронизация при восстановлении соединения.
  - Прецедент завершается успехом (с флагом «ожидает синхронизации»).

## UC6: Добавить задачу в список

| Поле | Описание |
|---|---|
| **ID** | UC6 |
| **Название** | Добавить задачу в список |
| **Акторы** | Пользователь |
| **Краткое описание** | Пользователь добавляет новую задачу в существующий список дел. |
| **Предусловия** | Пользователь аутентифицирован. Выбран конкретный список дел. |
| **Постусловия** | В выбранном списке появляется новая задача. |

### Основной поток событий

1. Пользователь открывает существующий список дел, нажав на него в общем списке.
2. Система отображает список и перечень вложенных задач.
3. Пользователь нажимает кнопку «Добавить задачу» (FAB «+»).
4. Система открывает экран редактирования задачи с полями: «Название», «Описание», «Дата», «Время».
5. Пользователь вводит название задачи.
6. Пользователь при необходимости заполняет описание, выбирает дату и время.
7. Пользователь нажимает кнопку «Сохранить».
8. Система проверяет, что поле «Название» не пустое.
9. Система создаёт объект `Задача`, связывает его с текущим списком, присваивает статус «ОЖИДАЕТ».
10. Система сохраняет задачу в локальной БД и синхронизирует с сервером.
11. Система возвращает пользователя на экран списка, отображая новую задачу в перечне.

### Альтернативные потоки

- **8а. Пустое название:**
  - Система выводит сообщение «Введите название задачи».
  - Возврат к шагу 4.

- **10а. Ошибка сохранения на сервере:**
  - Задача сохраняется локально, синхронизация при восстановлении соединения.
  - Прецедент завершается успехом (с флагом «ожидает синхронизации»).

## UC2: Войти в систему

| Поле | Описание |
|---|---|
| **ID** | UC2 |
| **Название** | Войти в систему |
| **Акторы** | Пользователь |
| **Краткое описание** | Пользователь вводит логин и пароль, получает JWT-токен для доступа к API. |
| **Предусловия** | Пользователь зарегистрирован в системе. |
| **Постусловия** | Пользователь аутентифицирован, JWT-токен сохранён на устройстве. |

### Основной поток событий

1. Пользователь открывает приложение, отображается экран входа.
2. Пользователь вводит логин (email) и пароль.
3. Пользователь нажимает кнопку «Войти».
4. Мобильное приложение отправляет POST-запрос `/api/auth/login` с учётными данными.
5. Сервер проверяет логин в БД, сравнивает BCrypt-хеши паролей.
6. Сервер генерирует JWT-токен и возвращает его в ответе.
7. Приложение сохраняет токен в SharedPreferences.
8. Приложение переходит на главный экран (список папок).

### Альтернативные потоки

- **5а. Неверные учётные данные:**
  - Сервер возвращает HTTP 401.
  - Приложение отображает сообщение «Неверный логин или пароль».
  - Возврат к шагу 2.

- **4а. Нет соединения с сетью:**
  - Приложение отображает сообщение «Нет подключения к серверу. Проверьте интернет-соединение.»
  - Прецедент завершается неуспехом.
